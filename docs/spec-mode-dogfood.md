# Spec mode 완주 점검 — 실행자용

> 계획서 §16 성공 기준 6번(도그푸드). **이 문서는 실행을 대신하지 않는다** — 실제 트래커,
> 실제 자격증명, 세 번의 승인이 필요하고 그것은 사람이 한다.
>
> 목적은 *"되는지 보는 것"* 이 아니라 **막히는 자리를 기록하는 것**이다.

## 실행 전에

| 준비 | 확인 |
|---|---|
| 설정 | 마법사 5단계 완료 (AI · 저장소 · 트래커 · 워크스페이스 · 채널) |
| 스펙 모드 | 설정 → 환경설정 → **계획 방식** → *요구사항·설계·태스크* |
| 이슈 | **아직 구현 안 된 것.** 이미 된 이슈를 넣으면 A1 이 "이건 이미 됐는데 뭘 원하나" 라고 질문을 쓴다 (실제로 겪었다) |
| 예산 | 이슈 하나에 계획 9회 + 태스크 수만큼. 하루 상한이 운영 AI 와 한 통이라는 것을 기억할 것 |

**작은 이슈로 시작할 것.** 태스크 3~5개짜리가 좋다. 첫 완주에서 보려는 것은 규모가 아니라
이음매다.

## 무엇을 보는가 — 단계별

### 1. 요구사항

- [ ] 카드 배지가 **요구사항**이고, 한 줄 설명이 *"무엇이 참이어야 하는지를 승인합니다"* 다
- [ ] 수용 기준에 `REQ-1`, `REQ-2` … 가 붙어 있다
- [ ] EARS 형태다 — `THE SYSTEM SHALL` / `WHEN` / `WHILE` / `IF … THEN` / `WHERE`
- [ ] **버그 이슈라면** `Current` · `Expected` · `Unchanged Behavior` 세 절이다
- [ ] 단계 막대가 8칸이고 두 번째(요구사항)에 서 있다

> **여기서 질문 카드가 뜨면** — 답하면 요구사항 단계로 돌아와야 한다. 계획 카드가 뜨거나
> *"Plan file is empty"* 가 나오면 그것을 기록할 것.

### 2. 설계

- [ ] 각 설계 판단이 `REQ-n` 을 가리킨다
- [ ] 어느 요구사항도 안 덮이면 그렇다고 적혀 있다
- [ ] 대안이 여럿이면 선택지가 뜬다 (이 단계에만)

### 3. 태스크

- [ ] 체크박스 목록이고 각 줄이 `REQ` 를 부른다
- [ ] **선택지가 안 뜬다** — 설계 대안이 여기 다시 나오면 기록할 것
- [ ] 불변 요구사항(`SHALL CONTINUE TO`)에는 태스크가 없다 — 정상이다

### 4. 구현

- [ ] 진행률이 `태스크 1/5` → `2/5` … 로 올라간다
- [ ] 각 태스크가 **자기 커밋**을 남긴다
- [ ] `⚠️` 가 뜨면 `tasks.md` 에서 읽지 못한 줄이 있다는 뜻 — 그 파일을 열어 볼 것
- [ ] *"T3 을 완료로 표시했지만 커밋이 없다"* 가 뜨면 그 태스크를 확인할 것

**중간에 앱을 껐다 켠다.** 이 점검의 핵심 중 하나다.

- [ ] 남은 태스크부터 재개된다 — 처음부터 다시 하지 않는다
- [ ] 진행률이 껐을 때 그대로다

### 5. 리뷰 → PR

- [ ] 리뷰 본문에 `## Acceptance criteria` 절이 있고 `REQ` 별 충족/미충족이 적혀 있다
- [ ] 미충족이 있으면 자동 PR 로 안 넘어간다
- [ ] PR 이 열린다

### 6. 끝난 뒤

- [ ] 대시보드 **스펙** 버튼으로 세 문서를 다시 볼 수 있다

## 비용 재기 — 계획서 §9 의 2.4배 추정과 비교

| 재는 곳 | 무엇 |
|---|---|
| 이슈 카드의 `$…` | 이 이슈에 든 총액 |
| 파이프라인 화면 헤더 | `개발 620k · 운영 80k` — 축별 몫 |

**같은 크기의 이슈를 `single` 로도 한 번 돌려** 비교하는 것이 가장 정확하다. 그게 부담이면
호출 횟수만 세도 된다 — 계획 9회 + 태스크 수 + 리뷰·PR 3회.

기록할 것: **이슈 크기(태스크 수) · 총액 · 호출 횟수 · §9 추정과의 차이.**

## 막혔을 때 무엇을 남기나

고칠 것을 판단하려면 다음이 필요하다.

1. **어느 단계에서** — 요구사항/설계/태스크/구현/리뷰 중 어디
2. **화면이 뭐라고 했나** — 문구 그대로
3. **`.corral/` 안이 어땠나** — 워크스페이스의 `spec/` 세 파일과 `question.md`
4. **로그** — 그 시각 전후

**에이전트 쪽 세션 기록도 볼 것.** corral 로그에는 없고 CLI 세션 기록에만 있는 경우가 있다
(CRL-89 가 그렇게 진단됐다).

## 이미 알고 있는 한계

실행 중에 마주쳐도 결함이 아니다.

- **태스크는 순차로만 돈다.** 의존이 없어도 동시에 안 돈다
- **진행 중이던 이슈는 마이그레이션되지 않는다.** 단일 계획으로 시작한 이슈는 그대로 끝난다
- **`tasks.md` 가 형식을 벗어나면** 단일 구현으로 내려간다. 화면에 그 사실이 뜬다
- **불변 요구사항에 태스크가 없는 것**은 정상이다
