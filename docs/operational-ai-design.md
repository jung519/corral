# 설계서 — 운영 AI (Operational AI)

> 성격: **설계 결정서**. 학습·조사 기록은 `sdd-and-operational-ai-study.md`에 있고, 이 문서는
> 그 위에서 **확정된 결정과 그 근거**만 담는다. 코드는 아직 없다.
>
> ⚠️ **corral은 특정 프로젝트에 의존하지 않는다.** 이 문서에 등장하는 sojan/refinery는
> **첫 검증 사례**일 뿐이며, 스키마·어댑터·용어는 전부 도메인 중립으로 정의한다.

---

## 1. 무엇을 만드는가

corral에 **두 번째 기둥**을 세운다.

| | 개발 AI (기존) | **운영 AI (신규)** |
|---|---|---|
| 단위 | 이슈 1건 | **파이프라인 실행 1건** |
| 수명 | 수십 분 | 수 초 |
| 형태 | 멀티턴 + 도구 + 파일 핸드오프 | **1턴, 구조화 출력** |
| 결과 | Pull Request | 검증된 JSON → 외부로 전달 |
| 사람 | 계획·리뷰 승인 | 저신뢰 건 검수(외부 위임) |

운영 AI는 **"이벤트가 오면 → 데이터를 정제·분류하고 → 결과를 돌려주는"** 반복 작업을
corral이 실행·관제하는 것이다. 비즈니스 로직은 실행하지 않는다.

### 경계 (개념도 기준)

```
① 원천 데이터 ──이벤트──▶ ② 운영 AI ──▶ ③ 판단 ──▶ ④ 비즈니스 로직
   (사용자 시스템)        ★ corral      (사용자 코드)   (사용자 코드)
                            │
                       확신 낮으면 → 사람 검수(사용자 시스템)
```

**corral이 가져가는 것은 ②뿐이다.** ①③④는 사용자 시스템에 남는다.

## 2. 핵심 개념 — 파이프라인

사용자가 화면에서 다루는 단위는 **파이프라인**이다.

```
파이프라인 = [트리거] → [입력 해석] → [AI 오퍼레이션] → [출력]
```

| 구성 | 역할 | corral이 아는 것 | 사용자가 정하는 것 |
|---|---|---|---|
| **트리거** | 일감 수신 | 큐/HTTP/스케줄/수동이라는 **종류** | 어느 토픽·어느 주소 |
| **입력 해석** | 이벤트 → AI 입력 | "이벤트 본문 그대로" 또는 "**ID로 조회**"라는 방식 | 어느 URL·어느 필드 |
| **AI 오퍼레이션** | 프롬프트·스키마·검증 | 구조화 출력 + **범용 검증 규칙** | 프롬프트 문장·허용값·임계값 |
| **출력** | 결과 전달 | 큐/HTTP라는 **종류** | 어느 엔드포인트 |

**오퍼레이션**은 파이프라인 안의 AI 단계 하나를 가리킨다(입력→프롬프트→스키마→검증→결과).

## 3. 확정된 결정

### 3.1 배포·실행

| # | 결정 | 근거 |
|---|---|---|
| D1 | **VM 1대에 corral 1개** — 개발 AI·운영 AI 모두 여기서 실행 | 운영 AI는 상시 가동이어야 하고, 상한을 공유하려면 인스턴스가 하나여야 한다 |
| D2 | UI는 **원격 제어평면**을 신설해 접속 | ⚠️ 현재 corral은 **헤드리스로 못 돈다**(§6.1) |
| D3 | **로컬 데스크톱 앱 → 원격 코어** 방식을 우선. 브라우저 접속은 후순위 옵션 | 사용자가 브라우저 UI를 원치 않음. 두 방식은 **코어 작업을 공유**하므로 나중에 추가해도 낭비가 없다 |
| D4 | 접속은 **터널(SSH/Tailscale) 위**를 기본 전제 | 포트를 공개 인터넷에 열지 않는다 |

### 3.2 파이프라인 구성

| # | 결정 | 근거 |
|---|---|---|
| D5 | 트리거는 **큐 어댑터**가 기본, 첫 구현은 **Pub/Sub**. 스케줄·수동 실행 병행 | 포트를 열지 않아도 되고, 발행자가 구독자 위치를 모른다 |
| D6 | 입력은 **fetch-back** — 이벤트에는 식별자만 오고, corral이 **처리 시점에 조회**한다 | 큐 대기 중 원본이 바뀔 수 있다. 데이터를 실어 보내면 낡은 값으로 처리된다 |
| D7 | 조회 어댑터는 **`none`(이벤트 본문 사용)** + **`http`** 둘로 시작 | HTTP 하나가 REST·GraphQL·자체 API를 모두 덮는다(GraphQL은 `POST + JSON 본문`). DB 직접 연결은 저장소마다 어댑터가 늘고 결합도가 높아 **코드 플러그인**으로 미룬다 |
| D8 | 출력은 **메시지 발행 또는 API 호출**, 사용자가 설정 | corral은 도메인 스키마를 모른다. 결과를 저장하는 것은 사용자 시스템의 몫 |
| D9 | 오퍼레이션 정의는 **YAML 선언**이 기본, **코드 플러그인 탈출구**를 처음부터 설계 | 선언으로 안 되는 오퍼레이션이 반드시 나온다. 나중에 넣으면 마이그레이션이 생긴다 |
| D10 | 선언 스키마는 **코드 오퍼레이션의 부분집합**이 되도록 잡는다 | 위와 같은 이유 |

### 3.3 안전·한도

| # | 결정 | 근거 |
|---|---|---|
| D11 | 상한 단위는 **토큰** | 금액은 단가표에 의존하고 단가는 벤더가 바꾼다. 토큰은 응답이 알려주는 정확한 값이다 |
| D12 | 상한은 **개발·운영 공유(선착순)**. 한쪽이 소진하면 둘 다 멈춘다 | 사용자 결정. 하위 배분은 두지 않는다 |
| D13 | 상한 카운터는 **하나의 corral 인스턴스 안에서만** 보장 | D1로 인스턴스가 하나라 충분하다 |
| D14 | 사람 검수는 **딥링크**로 시작 — corral은 "검수 필요 N건"만 표시하고 외부 관리 화면으로 보낸다 | corral이 도메인 데이터를 그리지 않아도 된다. 실제 빈도를 본 뒤 corral 내 검수로 고도화 |

### 3.4 저장·인증

| # | 결정 | 근거 |
|---|---|---|
| D15 | 실행 이력은 **JSONL 일별 롤링 + 일별 집계 파일** | 네이티브 모듈 0개를 유지해야 크로스빌드가 유지된다(§6.2). 볼륨상 충분하다 |
| D16 | `OpsHistoryStore` 인터페이스를 먼저 두어 저장소를 교체 가능하게 한다 | 볼륨이 커지면 SQLite/DB로 이전 |
| D17 | 인증은 **페어링 코드** — 최초 연결 시 코어가 짧은 코드를 표시하고, 앱이 입력하면 토큰을 교환·저장 | 긴 토큰을 복사·붙여넣지 않아도 된다 |
| D18 | 기본 바인딩은 **127.0.0.1**. 외부 노출은 명시적 옵트인 | 실수로 열어두는 사고를 구조적으로 막는다 |

### 3.5 UI

| # | 결정 |
|---|---|
| D19 | 첫 화면에서 **개발 / 운영** 선택. **마지막 선택을 기억**하고, 헤더에 현재 모드를 텍스트로 표시 |
| D20 | 운영 화면은 **세로 리스트** — 한 줄이 파이프라인 하나. 상세는 클릭해서 진입 |
| D21 | 파이프라인 추가는 **3단계 팝업**: ① 이벤트 수신 ② AI 에이전트 설정 ③ 결과 전송 |
| D22 | 입력 조회(D6)는 **①단계 안의 하위 설정**으로 접는다 — 단계를 4개로 늘리지 않는다 |
| D23 | AI 설정(②)은 **모델 스펙 + 판단 상세**(프롬프트·출력 스키마·검증 규칙)를 모두 담는다 |
| D24 | AI 프로바이더·상한 등 **기본 설정은 개발·운영이 공유**한다 |

## 4. UI 설계

### 4.1 화면 구조

```
[첫 화면]  개발  |  운영          ← 마지막 선택 기억
                 │
        ┌────────┴────────┐
     [개발]              [운영]
   기존 대시보드      헤더: 모드 표시 · 오늘 사용량/상한 · 큐 상태
                     ─────────────────────────────────────
                     ● 파이프라인 A   pub/sub → claude · 오늘 128건   [실행]
                     ● 파이프라인 B   pub/sub → gemini · 오늘 30건    [실행]
                     ○ 파이프라인 C   http → gpt · 비활성             [실행]
                                                          [＋ 파이프라인 추가]
```

- **한 줄 = 파이프라인 하나**(D20). 표시: 활성 여부 · 이름 · 트리거→프로바이더 · 오늘 건수 ·
  처리 중 / 저신뢰 / 실패 수 · 수동 실행 버튼
- **상한은 헤더에 상시 노출** — 개발 AI가 공유 상한을 잠식하면 즉시 보여야 한다(D12)
- 클릭 → 상세: 실행 이력, 토큰·비용, 검수 대기 딥링크(D14)

### 4.2 파이프라인 추가 팝업 (D21)

```
1. 이벤트 수신
   트리거:  ( ) HTTP   (•) Pub/Sub   ( ) 큐   ( ) 스케줄
   ────────────────────────────────────────────
   입력 데이터:                                   ← D22: 여기에 접어 넣는다
     ( ) 이벤트 본문을 그대로 사용
     (•) 받은 식별자로 조회   →  [ HTTP ▾ ]  URL 템플릿 · 헤더 · 응답 필드 매핑

2. AI 에이전트 설정                                ← D23
   모델·프로바이더 / effort / 최대 토큰
   프롬프트(역할·규칙)
   출력 스키마
   검증 규칙: 허용값 목록 · 최대 개수 · 최소 신뢰도 · 파생 필드 · 스킵 조건

3. 결과 전송
   ( ) HTTP 호출   (•) 메시지 발행   → 엔드포인트·토픽 설정
```

## 5. 파이프라인 스키마 (초안)

도메인 용어를 쓰지 않는다. 아래는 **범용 이름**이며 어떤 프로젝트에도 적용된다.

```yaml
pipelines:
  - key: classify-record            # 파이프라인 식별자
    enabled: true

    trigger:                        # ① 일감 수신
      kind: pubsub                  # pubsub | http | queue | schedule | manual
      topic: <topic>
      subscription: <subscription>
      max_concurrent: 1             # 한도를 모르면 1부터 (실측 후 상향)

    input:                          # ①-하위: 이벤트 → AI 입력
      kind: http                    # none(본문 그대로) | http | plugin
      request:
        method: POST
        url: "https://<host>/api/records/{id}"
        headers: { authorization: "Bearer ${SECRET}" }
      select:                       # 응답 → 납작한 입력 필드
        title:   "data.title"
        detail:  "data.description"   # truncate: 700
        tags:    "data.keywords"
      require: [title]              # 없으면 스킵(재시도해도 같음)
      skip_if: "data.category.items 비어있지 않음"   # 중복 처리 방어

    agent:                          # ② AI 오퍼레이션
      provider: claude              # 미지정 시 전역 배치를 따름
      max_tokens: 4096
      prompt:
        system: |
          <역할·규칙>
        user_template: |
          제목: {{title}}
          설명: {{detail}}
      schema:                       # 구조화 출력
        type: object
        properties:
          items:      { type: array, items: { type: string } }
          confidence: { type: number }
        required: [items, confidence]
      validate:
        allowed_values:             # 허용 목록 밖 값은 버리고 기록
          field: items
          source: { kind: http, url: "https://<host>/api/vocabulary" }
        max_items:      { field: items, limit: 4 }
        min_confidence: { field: confidence, threshold: 0.7 }
      derive:                       # AI에 묻지 않고 코드로 계산
        groups: "parent_of(items) 중복 제거"

    output:                         # ③ 결과 전달
      kind: http                    # http | pubsub | queue
      request:
        method: PATCH
        url: "https://<host>/api/records/{id}"
        body: { groups: "{{groups}}", items: "{{items}}" }

    on_low_confidence:              # 저신뢰 처리(D14)
      action: report                # 저장하지 않고 이력에만 남긴다
      review_url: "https://<host>/admin/records/{id}"
```

**설계 원칙**
- 필드 이름에 도메인 개념(태그·축제·카테고리)을 넣지 않는다
- 검증은 **AI를 믿지 않는다** — 프롬프트에 규칙을 적어도 코드에서 다시 검사한다
- **AI에 묻지 않아도 되는 것은 묻지 않는다**(`derive`) — 모순된 답이 나올 여지를 없앤다

## 6. 선행 과제 (지금 구조로는 불가능한 것)

### 6.1 corral은 헤드리스로 돌지 않는다 ⚠️

- 헤드리스 엔트리(`src/main.ts`)가 없고 `start` 스크립트도 없다 — **README의 "Run headless"는 사실이 아니다**(수정 필요)
- 유일한 엔트리 `src/ipc-main.ts`는 **Electron이 IPC 채널로 fork**해야 제어가 된다.
  단독 실행하면 오케스트레이터는 뜨지만 승인·조작이 불가능하다
- renderer는 `window.corral`이 없으면 즉시 실패한다
- `WebChannel`은 이름과 달리 **HTTP 서버를 열지 않는다**(상태 보관용)

→ **원격 제어평면(WS + 페어링 인증)이 운영 AI보다 먼저 필요하다.**

### 6.2 네이티브 모듈을 늘리면 안 된다

- corral desktop은 **런타임 네이티브 의존성이 0**이라 Mac·Windows 크로스빌드가 단순하다
- 코어가 도는 Node 버전이 환경마다 다르다: **VM 헤드리스 = Node 24**(`node:sqlite` 가능),
  **데스크톱 = Electron 33의 Node 20**(불가)
- → 이력 저장소는 **JSONL**(D15). SQLite/DB는 인터페이스 뒤로 미룬다(D16)

### 6.3 원격 모드에서 네이티브 기능의 소재지

| 기능 | 향하는 곳 | 이유 |
|---|---|---|
| 설정·시크릿·방향성 | **원격(VM)** | 코어가 실제로 읽는 값 |
| Docker/CLI 감지 | **원격(VM)** | 워크스페이스가 거기서 돈다 |
| **프로바이더 로그인 캡처** | **로컬** | **로컬에는 브라우저가 있다** — VM의 OAuth 문제가 여기서 풀린다 |
| OS 알림 | 로컬 | 사용자가 보는 곳 |

시크릿은 키체인이 아니라 **환경변수 + 파일(0600)**로 해결된다 — 코어에 이미 구현돼 있다.
